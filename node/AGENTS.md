# Lessons: Node service and the Mesh

Area gotchas that are still true. Claude Code loads this file (through `CLAUDE.md`) only once a session reads a file in this folder; other agents read the nearest `AGENTS.md`. Add a line when something here breaks, surprises you or takes more than one try; delete a line once your change makes it untrue. Repo-wide lessons: `docs/agents/lessons.md`.

- **Tests start Nodes with `MeshedNodes`**, a thin fixture over `sandbox.SimulatedNodes` (the in-process Nodes and in-memory Mesh the Sandbox also runs on). Each test Node gets its own folders under `tmp_path`; a new setting that touches disk belongs in `SimulatedNodes.settings`. A Node hears only what is published after it joins. `advance(seconds)` moves the injected clock, not a loop's real sleep; in a Replay it moves the Event clock 30 times as far.
- **The Sandbox registers its Sensors through the real routes** (`/api/registry/signup`, then `/accept` on the Hub), and its Nodes' ids are their names. It drives them with `TestClient`, whose `with` is what starts a Sensor's publishing loops; a test that serves `sandbox.hub` itself gets the Hub's loops only from its own `with`.
- **`InMemoryNetwork` has a 1 km radio range by default; `SimulatedNodes` (so `MeshedNodes`) makes it unlimited**, so tests never need positions. A test about reach builds its own `InMemoryNetwork` and places Nodes (`join(..., position=)`, `move`, `set_radio_range`). The range is a model of who hears, not proven on a radio or a Pi.
- **The Sandbox starts at 40 km, not 1 km**, because its Replay Nodes are up to 33 km apart; the dashboard slider and `POST /api/sandbox/radio-range` change it. Every Node joins at its settings' `latitude`/`longitude`. A Node's first reading goes out as it joins and only reaches the Hub if the Nodes between are already there, so `SENSOR_SITES` runs nearest the Hub first, and Sensors sign up only after all have joined.
- **`GET /api/sandbox/nodes` calls each Node's own `/api/state`** to learn who heard the newest Community Warning; "heard" is what that Node actually heard, so a Node cut off after hearing keeps its tick. A test puts a surge on the Mesh with `sandbox.network.deliver(sender, CommunityReading(...))`, two readings 8 s apart in `t`.
- **The Sandbox moves a Sensor by changing its `Settings`** (`SimulatedNodes.move`) and having it share a reading at once (`app.state.share_reading`); the publisher asks for its position and River km at each share. A spot's River km is the nearest point of the pack's river line within 500 m (`river_line.py`); farther off is dry and sends no `water_level`. Added Sensors are `s4`, `s5`, ... and a number is never reused (a returning id restarts at seq 0 and the Hub hides it). The registry packet caps the Sandbox: past it the Hub answers 409 and the new Sensor is not kept. A removed Sensor stays in the Hub's `/api/state` as a stale Node.
- **Strict counting:** no registry heard means nobody counts toward Flood Risk. `MeshedNodes.register(*names)` after the last `start(...)`; with a running `start_hub()` register through `/api/registry/signup` and `/accept` instead.
- **A Hub entered with its lifespan would call real services** (Open-Meteo): inject an offline `weather_source` as `MeshedNodes.start_hub` does.
- **Background loops only run under `with TestClient(app)`**; a bare `TestClient(app)` never starts them. A Node shows Mesh-only until its first connectivity probe answers.
- **Adding a field to a reading or a `/api/state` Node entry breaks two exact-field tests** (`test_community_reading.py`, `test_state_snapshot.py`). A reading's values are Measurements (`m`, `[kind, value, unit]`); build a hand-fed one with `MeshedNodes.hear_from(..., leaving_out=..., also=[Measurement(...)])`.
- **Each mesh message kind has its own `v`** (`reading` and `replay` are 2, the rest 1); `decode_message` reads it from the class, so a version bump is a one-line change on that class.
- **A Sensor reads the Event's surface only at a `NODE_RIVER_KM` inside the stations' span** (`MeshedNodes.start_sensor(river_km=...)`); anywhere else it gets the Event's weather and no `water_level`. A stopped Event clock reads the Event's first moment.
- **A Node cannot be walked through a storm**; it reads the Event's surface. Feed storm values to the rules with `MeshedNodes.hear_from(name, ...)` under a name no started Node has (a taken name raises), and build a hand-made `CommunityReading` with `meshed_nodes.a_calm_day()`.
- **Surges are judged on the sender's timestamps**, and `surged` is "surging now", not latched (it clears about 60 s after the jump). A Surge is 300 cm or more within 60 s.
- **One signed Reticulum packet is 464 bytes**, which caps a registry (4 to 8 Nodes) and an Official Alert's headline.
- **Shelter status and the registry are trusted only from `HUB_IDENTITY`**; a blank or wrong id drops them silently. When a Node shows nothing open, or a Sensor ignores the Replay, check `HUB_IDENTITY` first (printed as `Node <id> (...) is up as hub`; it changes if `NODE_DATA_DIR` is wiped).
- **A Node logs "is up" before it binds HTTP**, so that line does not prove it is serving.
- **Loopback groups:** a Node dials every slot from `NODE_LOOPBACK_FIRST_SLOT` to its own. A group not starting at 0 must set it, or it joins every Node below. A taken slot fails with exit 255 and an empty log.
- **`CACHE_PACK_URL`, `CACHE_PACK_DIR`, `CARTO_API_KEY` and the alert email settings are read unprefixed and only from the environment** (`Settings` has no `env_file`); `run-live.sh` and `run-demo.sh` load `.env`, anything else must export it. `.env` is sourced by bash: quote values with spaces.
- **A Node never re-downloads a valid Cache Pack**: delete `CACHE_PACK_DIR` (and the Hub's `shelter_status.json`) to change packs.
- **Never log `httpx` errors whole**: their message holds the URL, and the URL can hold a key. `create_app` keeps the `httpx` logger at WARNING for the same reason.
- **`RNS.Identity.from_file` returns `None` on a damaged file** and `to_file` writes 644; `load_or_create_identity` handles both.
- **Mesh decode and delivery go through `mesh.decode_message` and `deliver_to_listeners`** for both Meshes; add rules there.

Networking and Pi lessons (firewalls, TCP peers) are in `pi/AGENTS.md`.
