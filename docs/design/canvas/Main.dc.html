Storm Shield · UI design reference

The visual source of truth for the dashboard: every view, every state, every control and every icon. Build tickets from these artboards; the prose rules are in docs/design/ui.md and the words in CONTEXT.md.

How this canvas is organized

FoundationsColor roles, type, spacing, motion and performance, icons.
ComponentsEvery control and building block with all of its states.
DesktopThe projected Hub and resident laptops: 1440 × 900 at 120%.
PhoneResidents on the Node Wi-Fi: 390 × 844, four tabs.
FlowsThe 3-minute demo, beat by beat, and every state transition.
God's Eye ViewThe desktop map of Nepal from real geometry: calm, 3D valley, the warning, contact lost, the corner card options. Decisions D-01 to D-55.

Principles

01The map is the pageIt fills the screen. Panels float over it and collapse; the map never shrinks to a cell.
02Every change is visibleWhen a number, level or connection changes, it moves once, smoothly, in place. Nothing jumps, nothing loops.
03Official never looks communityOfficial Alerts are the only light panels. Community Warnings are dashed violet. Nobody can mix them up.
04Say where a number came fromSIMULATED, STALE, NOT COUNTED, OFFLINE: always a word, never just a quieter color.
05Phone first, offline alwaysResidents open this on a phone over the Node Wi-Fi. Nothing core needs the internet, fonts included.
06One kit, one themeEvery control comes from the Components page. Every color is a role from one theme file.

Changing the design

Expect small changes once the dashboard is in real hands.

Polish goes code-firstSpacing, copy, timing, colors within the roles: change the code, then sync this canvas in one batch at the end of the day.
Anatomy goes canvas-firstA new element, a moved Panel, a new state: add or change the artboard here first, then build it.
Tokens are owned by codeThe theme file in dashboard/src/ owns primitives and roles. This canvas links a copy of it (theme.css).
