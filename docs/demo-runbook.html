If it breaks

Most common causes first.

The projector shows an old dashboard or old data

A stale Node is still on port 8000. Run scripts/stop-nodes.sh, then start again. The Hub logs "is up" before it binds its port, so the log line alone does not prove it is serving.

The map is blank

The Hub has no Cache Pack. Check .demo/pack/cache-pack.zip exists and .demo/logs/hub.log for checksum errors. If shelters look like Gainesville ones and are all Closed, it holds an old pack: stop, delete .demo/pack/ and the Hub's shelter_status.json, and restart.

A Sensor does not move with the Replay

It needs the Hub's identity (HUB_IDENTITY). The script sets it after the Hub starts. If the Hub restarted with a wiped .demo/hub/data, its id changed, so restart the whole demo.

Flood Risk or warnings never react

A Sensor is probably not registered. Check the Registry tab, and look for "could not register" in the script output. Also confirm the Replay is running, not paused.

No phone can reach the dashboard

Confirm the phone is on the same network, use the exact address the script printed, and check the laptop firewall. On Tailscale, run tailscale status; it may be stopped.

An audience laptop never hears the Hub
  • firewalld: sudo firewall-cmd --zone=<zone> --add-port=29716/udp --add-port=42671/udp
  • Docker on the Hub laptop blocking sharing: sudo iptables -I DOCKER-USER -i <cable> -o <wifi> -j ACCEPT
  • macOS firewall: allow incoming for Python, or switch it off for the demo
  • Guest or hotel Wi-Fi that isolates clients
  • In Docker without host networking, check that the Hub's TCP port 4242 is reachable
No warning email arrives

It needs internet and all three ALERT_EMAIL_* values. A failure logs "could not email the flood alert" in .demo/logs/hub.log. The first warning comes before the 09:20 cue, so it normally goes out.
